# 验证记录

日期：2026-10-11。

环境：Windows、Python 3.11.4、FFmpeg 9.0 Full Build（Gyan）。

本文记录首次交付时的验证结果。整理 Git 仓库时已清除测试代码、合成示例媒体和临时产物，保留本记录及界面预览作为项目文档。

## 自动化验证

首次交付时运行 `python -m unittest discover -s tests -v`：**10 项集成测试全部通过**。

验证采用实际生成的双音轨视频和 FFmpeg 执行结果，包括：

- 33 种 Moo0 对应格式全部生成非空音频，非原始格式使用 FFprobe 确认没有视频流。
- 44,100 Hz、单声道、24 位 WAV 的实际文件参数。
- 320 kbps MP3 的实际码率。
- 无损提取前后 AAC 音频包 SHA-256 与解码后的 PCM SHA-256 一致。
- 50% 音量的音频均方根振幅比例约为 0.5。
- 选择第二音轨后，输出对应 880 Hz 的示例音轨。
- 24/32 位与 32 位浮点的 WAV、AIFF、AU、FLAC、ALAC 和原始 PCM 变体。
- Yamaha WAV、GSM WAV、MMF、RA、OGG FLAC 及原始 PCM 的试听输出。
- 损坏文件、无音轨视频、无效参数的拒绝处理。
- HTTP 流式读取、单文件下载、Range 下载、ZIP 下载与会话 / 跨站访问检查。
- 排队与执行中的任务取消，未完成文件清理，同名文件编号，原文件与输出文件保留。
- 服务重新加载后恢复已完成记录及输出文件。

运行 `node --check web/app.js`：**通过**。

## 浏览器验证

在本机网页中实际完成：

- 文件选择导入当时生成的双音轨合成示例，正确识别两个音轨。
- 选择第二音轨，设置 44,100 Hz、单声道、24 位，成功输出 WAV。
- 点击试听，浏览器读取到 4 秒音频，播放就绪，没有音频错误。
- 切换英文，进入转换记录，通过网页成功下载 ZIP。
- 切回中文，选择原始音轨，再次转换成功生成 M4A，显示无损复制。
- 服务重启后，网页仍显示两条已完成转换记录。

## 启动脚本

- `launch.ps1 -NoBrowser` 成功启动，服务报告 33 个可用格式。
- 重复运行启动脚本，进程 ID 保持一致。
- `stop.ps1` 成功停止服务并清理运行实例信息。
- 再次启动成功，已完成记录恢复。
